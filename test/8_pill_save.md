# 의약품·영양제 보관함

수동 검증 시나리오입니다. 코드 대조로 정리했으며 기기에서 통과한 결과를 의미하지 않습니다.

| 구분             | 확인 절차 및 기대 결과                                                                                      |
| ---------------- | ----------------------------------------------------------------------------------------------------------- |
| 폴더 제한        | 폴더 최대 100개, 폴더당 항목 최대 1,000개, 복사 대상 최대 20개 제한을 경계값에서 확인한다.                  |
| 이름 검증        | 입력 UI 최대 255자, 빈 이름·공백·중복·금지 문자 처리와 앞뒤 공백 제거를 확인한다.                           |
| 기본 폴더        | 기본 폴더는 이름 변경·삭제·다중 선택이 제한된다.                                                            |
| 폴더 관리        | 새 폴더 생성·이름 변경·삭제 확인·키보드 노출 시 입력 영역을 확인한다.                                       |
| 정렬             | 기본값은 이름순(name_asc)이며 생성일·최신순·이름순·항목 수 정렬을 변경하여 확인한다.                        |
| 편집             | 편집 중 하단 탭 숨김, 선택 개수, 전체 선택·해제, 이동·복사·삭제를 확인한다.                                 |
| 혼합 저장        | 같은 폴더에 의약품과 영양제를 저장하고 개수·목록·폴더 프리뷰를 확인한다.                                    |
| 식별자 충돌      | 동일 원시 번호의 의약품과 영양제도 functional-food: 접두어로 별도 항목이 된다.                              |
| 상세 분기        | 의약품은 ITEM_SEQ로 의약품 상세, 영양제는 reportNumber로 영양제 상세에 진입한다.                            |
| 이동·복사        | 이동은 하나의 대상, 복사는 여러 대상으로 수행한다. 대상 중복 시 중복 저장 안내와 원본 처리 결과를 확인한다. |
| 저장 해제        | 상세 폴더 모달에서 선택·해제를 변경하고 보관함에 반영되는지 확인한다.                                       |
| 알림 연계        | 의약품과 영양제를 알림 대상으로 선택하고 기존 알림 배지·항목별 알림 바텀시트를 확인한다.                    |
| 지속성·동시 작업 | 앱 재시작 후 항목이 유지되고 대량 이동·복사와 다른 DB 작업이 겹쳐도 중복·트랜잭션 오류가 없는지 확인한다.   |

구현 근거: `src/features/pill_save/`, `src/services/database/queries/saved_item_metadata.ts` (앱 저장소).
