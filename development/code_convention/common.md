# 공통 프로그래밍 규칙

## 네이밍 규칙
- 역할과 목적을 알 수 있도록 간결하고 명료하게 작성
- **상수명**: 언어 상관 없이 대문자 스네이크 케이스 (SNAKE_CASE)
- **함수명**: 동사 + 명사 + 전치사 구조 (예: `searchPillByImage`)
- **기타 파일명 (md 등)**: 스네이크 케이스 (snake_case)

## 주석 규칙
- 코드가 어떻게 동작하는지, 무엇을 하는지에 대해서는 작성 금지 (코드 자체가 설명이 되어야 함)
- 코드를 간결하게 짤 수 없거나 코드가 복잡하여 코드 자체만으로 판단할 수 없는 경우에만 작성
- 코드의 고칠점이나 유의사항이 있다면 [코드 태그](https://2mukee.tistory.com/599) (TODO, FIXME 등)를 활용
- **함수 주석**: 함수의 역할만 간단하게 설명

## 클린 코드 및 설계 원칙

### SOLID 원칙
1. **SRP (단일 책임 원칙)**: 클래스나 함수는 단 하나의 책임만 가져야 한다.
2. **OCP (개방-폐쇄 원칙)**: 확장에는 열려 있어야 하고, 변경에는 닫혀 있어야 한다.
3. **LSP (리스코프 치환 원칙)**: 자식 클래스는 언제나 부모 클래스를 대체할 수 있어야 한다.
4. **ISP (인터페이스 분리 원칙)**: 특정 클라이언트를 위한 인터페이스 여러 개가 범용 인터페이스 하나보다 낫다.
5. **DIP (의존성 역전 원칙)**: 추상화에 의존해야 하며, 구체화에 의존하면 안 된다.

### 기타 설계 원칙
- **DRY (Don't Repeat Yourself)**: 똑같은 코드를 반복하지 마라. 중복을 최소화할 것.
- **YAGNI (You Aren't Gonna Need It)**: 필요할 것이라고 예상해서 미리 구현하지 마라. 현재 필요한 기능만 구현할 것.
- **KISS (Keep It Simple, Stupid)**: 코드는 최대한 단순하고 명료하게 작성하라. 불필요한 복잡성을 피할 것.
