# 프론트엔드 코드 컨벤션

적용 대상은 `wip-application-v2`의 Expo·React Native·TypeScript 코드입니다. 실제 구현 구조와 예외는 [애플리케이션 구조](../application_architecture.md)를 참고합니다.

## 네이밍과 배치

- React 컴포넌트와 화면은 PascalCase의 `.tsx`, 훅·서비스·리포지토리·데이터 소스·타입은 역할을 드러내는 이름으로 작성합니다.
- 새 TypeScript 모듈은 기존 기능의 snake_case 규칙을 따릅니다. 기존 camelCase 파일은 불필요하게 일괄 변경하지 않습니다.
- 제품 설명은 의약품·복용 관리로 표현하고, 외형·이미지 식별에서 알약이라는 용어를 씁니다. 기존 `pill_*` 코드명은 유지합니다.
- 건강기능식품 조회는 `functional_food_search`, 공통 보관은 `pill_save`, 복용 일정은 `pill_reminder`의 책임으로 둡니다.

## 기능과 계층

- `app/`는 라우트와 화면 연결, `src/features/<feature>/`는 해당 기능의 UI와 로직을 담당합니다.
- 화면·컴포넌트 → 훅 → 서비스 → 리포지토리 → 데이터 소스 → 공통 API/DB 방향으로 책임을 나눕니다.
- 훅은 이벤트·포커스·생명주기를, 서비스는 유스케이스를, 리포지토리는 접근 경로 조합을, 데이터 소스는 실제 입출력을 담당합니다.
- SQL과 HTTP 요청을 화면에 추가하지 않습니다. 공통 데이터 접근은 `src/services/database/`, `src/services/apis/`를 사용합니다.
- 현재 영양제 훅의 직접 DB 호출과 스토어의 서비스 호출은 구현 현황입니다. 새 코드의 구조를 결정할 때 이를 모든 기능의 규칙으로 확대하지 않습니다.

## 상태와 렌더링

- 컴포넌트는 필요한 Zustand 상태를 선택자로 구독합니다. 화면 전체에서 스토어 전체를 구독하지 않습니다.
- 명령용 훅은 이벤트 시점의 값에 `getState()`를 사용하고, 입력·생명주기 훅과 책임을 구분합니다.
- 입력·모달처럼 해당 UI만 사용하는 상태는 로컬에 두고, 여러 영역이 공유해야 하는 상태만 공유 저장소에 둡니다.
- 반환하는 이벤트 핸들러는 필요한 경우 `useCallback`으로 안정화합니다. `memo`·`useMemo`는 실제 렌더링 비용을 기준으로 적용합니다.
- 비동기 검색은 이전 응답이 새 검색 결과를 덮지 않도록 요청 식별자·상태를 관리합니다.

## 데이터와 사용자 경험

- 저장된 영양제 항목은 `saved_item_identity.ts`의 변환 함수를 사용합니다. 의약품 품목번호와 영양제 신고번호를 같은 원시 ID로 저장하지 않습니다.
- SQLite 연결·트랜잭션·바인딩 분할은 공통 모듈을 사용합니다. 직렬화 트랜잭션 안에서 같은 래퍼를 중첩 호출하지 않습니다.
- 로딩·실패·빈 결과·일부 데이터 누락 상태를 구분합니다.
- 스타일은 별도 파일 또는 컴포넌트 하단 StyleSheet로 관리하고 재사용 스타일을 공유합니다.
- 새 가이드는 [적용 가이드](../guide_integration.md)를 따르며 루트 Provider·Overlay를 중복 추가하지 않습니다.
